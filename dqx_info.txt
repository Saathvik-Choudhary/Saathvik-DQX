DQX Info Document

Overview
DQX (Databricks Labs) is a data quality framework for Apache Spark that lets you define,
monitor, and act on data quality issues in Python-based pipelines. It works with PySpark
DataFrames, supports batch and streaming, and integrates with Databricks tools including
Lakeflow Pipelines (DLT). It provides row-, column-, and dataset-level rules, detailed
failure info, and flexible handling such as quarantining or annotating invalid data.

Sources:
https://databrickslabs.github.io/dqx/
https://databrickslabs.github.io/dqx/docs/motivation/

Key Capabilities
- Detailed failure reasons at row/column level
- Works with PySpark DataFrames and tables
- Batch + Structured Streaming + Lakeflow/DLT support
- Warning and error criticalities
- Row, column, and dataset-level rules
- Profiling and rule generation
- Summary metrics and quality dashboard

Source:
https://databrickslabs.github.io/dqx/

Installation
Library:
- pip install databricks-labs-dqx (pinning recommended)
- Optional extras: [llm], [pii], [datacontract]
- Requires Databricks cluster with Spark 3.5+ (recommended DBR >= 15.4)

Workspace Tool:
- databricks labs install dqx (pinning recommended)
- Requires Databricks CLI v0.241+, Python 3.10+, workspace access
- Installs workflows, dashboard, config, and wheel

Source:
https://databrickslabs.github.io/dqx/docs/installation/

Usage Modes
In-transit (code-level):
Apply checks while data is being processed, before writing.

At-rest (code or no-code workflows):
Run checks on persisted data via workflows (quality-checker, profiler, e2e).

Source:
https://databrickslabs.github.io/dqx/docs/guide/

Quality Checks
Ways to define checks:
- DQX classes (DQRowRule, DQDatasetRule, DQForEachColRule)
- Metadata (list of dicts)
- YAML/JSON files
- Delta tables

Applying checks (DQEngine):
- apply_checks / apply_checks_and_split
- apply_checks_by_metadata / apply_checks_by_metadata_and_split
- end-to-end methods to read, validate, and write results

Sources:
https://databrickslabs.github.io/dqx/docs/guide/quality_checks_definition/
https://databrickslabs.github.io/dqx/docs/guide/quality_checks_apply/
https://databrickslabs.github.io/dqx/docs/guide/quality_checks_storage/

Profiling and Rule Generation
Profiling generates summary stats and candidate rules.
Tools:
- DQProfiler (profile DataFrame/table)
- DQGenerator (generate rules)
- DQDltGenerator (generate DLT expectations)

Source:
https://databrickslabs.github.io/dqx/docs/guide/data_profiling/
https://databrickslabs.github.io/dqx/docs/reference/profiler/

AI-Assisted Features
AI rule generation:
- Generate rules from natural language via DQGenerator
- Requires databricks-labs-dqx[llm]

AI primary key detection:
- Detect PKs and generate uniqueness rules
- Requires databricks-labs-dqx[llm]

Sources:
https://databrickslabs.github.io/dqx/docs/guide/ai_assisted_quality_checks_generation/
https://databrickslabs.github.io/dqx/docs/guide/ai_assisted_primary_key_detection/

Data Contract Rules (ODCS)
Generate rules from ODCS v3.x data contracts:
- Predefined rules from schema constraints
- Explicit DQX rules
- Text-based expectations via LLM (optional)

Source:
https://databrickslabs.github.io/dqx/docs/guide/data_contract_quality_rules_generation/

Summary Metrics
Built-in metrics (input, error, warning, valid counts) plus custom SQL metrics.
Metrics can be persisted to tables for monitoring and alerting.

Source:
https://databrickslabs.github.io/dqx/docs/guide/summary_metrics/
